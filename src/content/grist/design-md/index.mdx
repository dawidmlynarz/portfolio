I wrote one for my own design system. Agents read files in the repo, not your documentation site, so this is the first thing they open. It links to the real tokens and components instead of copying their values, which keeps it from going stale. Once it existed, what the agents built came out more streamlined and consistent.

DESIGN.md is becoming a common name for this file, and that helps. An agent that has seen one before knows what to look for.

Don't paste token values in. Within a month they won't match the real ones.
