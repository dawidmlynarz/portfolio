Agent behaviour usually lives in a system prompt nobody designed. A spec makes behaviour a design decision the team can review, and the source the prompt is written from.

Watch for boundaries written as hopes ("be careful with payments"). Each boundary should be something a test could catch.

## Example

The _Checkpoints_ section for a group-travel agent: _Asks before: paying, cancelling a booking, emailing anyone outside the team. Acts and reports: searching, holding seats for up to 24 hours, drafting messages. Silence on a checkpoint means nothing happens._
