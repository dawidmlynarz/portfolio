Project context changes with every project. How you work doesn't. Splitting the two means you write your standards once.

Watch for writing aspirations ("be bold"). Every line should be something you could check in the output.

## Example

A filled "Red lines" section: _Never invent research findings or quotes. Never use colour alone to carry meaning. Never use placeholder text in anything I'll show a client. Never change the design system's tokens; suggest changes instead._
